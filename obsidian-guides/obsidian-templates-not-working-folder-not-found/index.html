Obsidian Templates Not Working? Fix "Failed to List Templates", Empty Template Lists and Daily Notes That Ignore the Template

The core Templates plugin is small: point it at a folder, pick a note, and its text lands in the note you're editing. When it fails, it usually fails quietly. "Failed to list templates. Folder … not found." A template list that's empty. A click that inserts nothing. {{date}} showing up as literal text. A new daily note that ignores your template. Each of these has a short list of causes. This checklist covers the core plugin only (no Templater).

Quick reference

Symptom Most likely cause Check
"Failed to list templates. Folder … not found" Folder set as a full disk path, or not inside the vault 2
Template list is empty Wrong folder, or the template isn't a note in that folder 2, 3
Click a template, nothing appears No active note in editing mode 4
<% … %> or other syntax left as text Core Templates only knows three variables 5
Date property comes out blank or wrong Unquoted variable overwritten by the Properties panel 6
New daily notes don't use the template Daily notes has its own template setting 7

☐ 1. Turn on the core plugin

Open Settings → Core plugins and enable Templates. Once it's on, the ribbon shows an Insert template button and the command palette has Templates: Insert template.

☐ 2. Set the template folder from inside the vault

Obsidian's help: under Settings → Core plugins → Templates → Template folder location, "enter the folder containing your templates."

  • Click the field and pick the folder from the suggestions, or start typing its name. Don't paste a path from Finder or File Explorer.
  • Note: Obsidian's help doesn't spell this out, but forum answers to the "Folder not found" error agree that the setting expects a folder inside the vault, written relative to the vault root (for example Templates), not C:\Users\…\Templates or /Users/…/Templates.
  • If the folder lives outside the vault, move it in. Create it from Obsidian's file explorer, so Obsidian sees it right away.

☐ 3. Make the template a note in that folder

A template is just a Markdown note in the template folder. Obsidian's help: "In the template folder, create a note containing the text you want to appear when you use the template."

  • Check that the file is really .md and sits in the folder you configured, not one level up.
  • Note: if the vault sits in a cloud-synced folder (iCloud Drive, OneDrive, Dropbox), files that are online-only placeholders can confuse Obsidian. Forum answers suggest making the vault folder available offline, or testing with a copy of the vault in a normal local folder.

☐ 4. Insert into an active note, in editing mode

Templates "insert pre-defined snippets of text into your active note". It doesn't create a new note by itself.

  • Open the note first, click into the body, then run Insert template. "The content of the template is inserted at your current cursor position. If your cursor is not in the note body, the content is inserted at your last cursor position."
  • Note: in one forum thread, nothing was inserted because the note was open in Reading view. Switch to Live Preview or Source mode and try again.
  • For speed, give Templates: Insert template a hotkey in Settings → Hotkeys.

☐ 5. Use only the variables core Templates supports

The help lists three template variables:

Variable Value
{{title}} Title of the active note
{{date}} Today's date, default format YYYY-MM-DD
{{time}} Current time, default format HH:mm

You can add a Moment.js format after a colon, such as {{date:YYYY-MM-DD}} or {{date:dddd, MMMM D}}. The defaults are set under Settings → Core plugins → Templates → Date format and Time format.

Note: the help lists no other variables. Syntax from other plugins, such as Templater's <% … %>, isn't documented for core Templates, so expect it to stay as plain text.

☐ 6. Protect variables inside properties

Obsidian's help warns that in Live Preview, "the Properties in document panel can overwrite template variables that do not have quotation marks."

  • In the template's properties, quote the variable: date: "{{date}}".
  • Edit template files in Source mode, or set Settings → Editor → Properties in document to Source.
  • After changing a template, insert it into a scratch note and check the properties before using it on real notes.

☐ 7. Daily notes: set the template there too

Daily notes uses its own setting. In Settings, open Daily notes under plugin options and set Template file location.

  • Pick your daily template note there. Help: "Obsidian uses the template the next time you create a new daily note."
  • That means existing daily notes don't change. To apply the template to today's note after the fact, open it and use Insert template.
  • The help also notes that {{date}} and {{time}} work in Daily notes and Unique note creator templates.

☐ 8. If a setting keeps reverting

Note: in a forum thread about the template folder "reverting" after it was changed, the suggested cause was the sync service the vault lived in. Pause sync, set the folder again and restart Obsidian. If it still reverts, test with a copy of the vault outside the synced folder.
