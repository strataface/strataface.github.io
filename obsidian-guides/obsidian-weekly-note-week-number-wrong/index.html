Obsidian Weekly Notes: Why the Week Number Is Wrong (and a Core-Plugins-Only Setup)

You name your weekly notes like 2026-W42. Most of the year that works, and then one week it doesn't. On 29 December the new note is called 2025-W01 instead of 2026-W01. Or every Sunday (or Monday) lands in the wrong week. Or a weekly note made by one plugin doesn't match the week number another plugin shows.

Almost every case comes down to the date-format tokens. Obsidian's date formats (in the Templates plugin, the Daily notes plugin, and most community plugins) use Moment.js format strings, and Moment has three "years" and two kinds of "week number". This checklist shows which tokens to use, then a weekly-note setup that needs only core plugins.

Quick reference

You want Use Example (Mon 29 Dec 2025)
ISO week (weeks start Monday, week 1 contains the first Thursday) GGGG-[W]WW 2026-W01
Locale week (follows the locale's first day of week) gggg-[W]ww depends on locale
Don't combine these YYYY-[W]WW 2025-W01 (wrong year)

[W] is a literal letter W. Square brackets stop Moment from reading it as a token.

☐ 1. Don't pair the calendar year with a week number

YYYY is the calendar year. WW is the ISO week number. Around New Year they disagree:

Date YYYY-[W]WW GGGG-[W]WW
Sun 28 Dec 2025 2025-W52 2025-W52
Mon 29 Dec 2025 2025-W01 2026-W01
Thu 1 Jan 2026 2026-W01 2026-W01
Thu 31 Dec 2026 2026-W53 2026-W53
Fri 1 Jan 2027 2027-W53 2026-W53

29 December 2025 is in ISO week 1 of 2026, so YYYY gives the right week with the wrong year. In the other direction, 1 January 2027 is still in week 53 of 2026. An Obsidian forum report of exactly this ("Expected result 2026-W01, Actual result 2025-W01") was answered by switching to the ISO week-year token GGGG.

Fix: use GGGG with WW, or gggg with ww. Never mix YYYY with a week token.

The table values come from Moment.js 2.x run outside Obsidian. Obsidian bundles its own Moment build, but these tokens are part of Moment's documented format set.

☐ 2. Pick ISO weeks or locale weeks, and use them everywhere

Moment has two week systems:

  • W / WW with GGGG is the ISO week. Weeks start on Monday, and the first week of the year is the one that contains the first Thursday.
  • w / ww with gggg is the locale week. The first day of the week and the first week of the year come from the locale. In Moment's default English (US) locale, weeks start on Sunday. Sunday 29 Sep 2024 is locale week 40 but ISO week 39.

If your daily notes put a Sunday in a different week than your weekly note does, one place is using ISO weeks and the other is using locale weeks. The Periodic Notes FAQ, quoted in an Obsidian forum thread, says it defaults to ww (week of year) and that WW gives the ISO week.

Note: which locale Obsidian passes to Moment depends on your app language and system settings. If you use ww/gggg, check a few Sundays and Mondays in your own vault. If you don't need locale weeks, ISO (GGGG-[W]WW) gives the same answer on every machine.

☐ 3. Check every place that writes a week number

One mismatched format is enough to break links between daily and weekly notes. Check:

  • Your weekly-note file name (however you create it).
  • Any {{date:…}} in your templates (below).
  • The Date format of the core Daily notes plugin, if you put the week in a daily note's path.
  • Community plugins (Periodic Notes, Calendar, Templater, Dataview) have their own settings.
  • Base formulas, if you use them. The forum answer above used now().format("GGGG-[W]WW").

☐ 4. A weekly note with the core Templates plugin

You don't need a community plugin to keep weekly notes. The core Templates plugin supports three variables: {{title}}, {{date}} and {{time}}. {{date}} and {{time}} accept a Moment format after a colon, for example {{date:YYYY-MM-DD}}.

  1. Settings → Core plugins → Templates → Template folder location: set it to your templates folder.
  2. Create a template like this:
---
week: "{{title}}"
created: "{{date:YYYY-MM-DD}}"
tags:
  - weekly
---

# {{title}}

## Shipped this week
-

## Next week: three things only
1.
2.
3.
  1. Create a new note, name it with the week (2026-W42), then run Templates: Insert template. {{title}} becomes the note's name.

Two details matter here:

  • Name the note first. {{title}} is the title of the active note when you insert the template.
  • {{date}} is today, not "the week this note is for". If you plan next week on a Sunday, {{date:GGGG-[W]WW}} gives this week's number. Use {{title}} for the week and keep {{date}} for "created on".

The Obsidian help warns that in Live Preview, the Properties panel can overwrite template variables that are not in quotation marks. Quote them, as in the example, and edit templates in Source mode.

☐ 5. Group daily notes by week, without plugins

The core Daily notes plugin only creates daily notes; there is no built-in weekly option. Its Date format can create folders, though. The help page's example YYYY/MMMM/YYYY-MMM-DD creates notes like 2023/January/2023-Jan-01. With an ISO-week folder:

GGGG-[W]WW/YYYY-MM-DD

each daily note lands in a folder such as 2026-W42/2026-10-14.

In the weekly note, list that week's daily notes with an embedded search. The core Search plugin renders a query code block, and path: matches text in the file path:

```query
path:"2026-W42/"
```

Note: the help page doesn't say what happens to daily notes you already have when you change the date format. Assume they are not moved or renamed, and try the change in a test vault first.

☐ 6. Make week names sort correctly

WW is always two digits (W05, not W5), so GGGG-[W]WW names sort in date order in the file explorer. Single-digit W doesn't: 2026-W10 sorts before 2026-W9.

Symptom table

Symptom Cause Fix
Late-December note named 2025-W01 YYYY with WW GGGG-[W]WW (step 1)
Early-January note named 2027-W53 YYYY with WW GGGG-[W]WW (step 1)
Sundays or Mondays land in the neighbouring week ISO week in one place, locale week in another Use one system everywhere (steps 2–3)
Weekly template shows this week when planning next week {{date}} is the insertion date Name the note, use {{title}} (step 4)

If you want the weekly system already built

If you'd rather start from a working vault than build the structure yourself, Indie Weekly ($39) is a ready-to-open Obsidian vault for indie developers. It covers planning the week, logging what shipped, tracking a few metrics and running a Friday review. According to its product page it includes 41 Markdown notes (a Home dashboard, a getting-started guide, a tag convention, a metrics cheatsheet and filled examples from a fictional indie SaaS that you can delete) and 8 templates, including weekly review, ship log, project, idea, decision and experiment. It uses core Obsidian settings only, with no community plugins required; optional ones are listed in its HOW_TO. You unzip it and use Open folder as vault. It is made for Obsidian desktop. Mobile hasn't been tested, and the page says the layout may differ there. Its templates use plain-text placeholders that you replace by hand, rather than date variables. If you only want the two core templates, Indie Weekly Lite is free: it has the Weekly Review and Ship Entry templates, without the other 6 templates or the full 41-note vault.
