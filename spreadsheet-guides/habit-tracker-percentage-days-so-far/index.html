Habit Tracker Percentage Wrong Early in the Month? Divide by Days So Far (Google Sheets)

You tick every habit for the first five days of the month, and your spreadsheet says you are at 16%. Nothing is wrong with your week. The formula is dividing five ticks by all 31 days of the month, including the 26 that have not happened yet. This checklist shows how to get two honest numbers instead: a month rate (done days ÷ days in the month) and a so-far rate (done days ÷ days that have passed). It also covers the edge cases that quietly break most trackers: 28/29/30-day months, ticks typed as 1 instead of checkboxes, and future or past months.

The formulas use COUNTIFS, EOMONTH, DAY, MIN, MAX, IF and TODAY, which exist in Google Sheets, Microsoft Excel and LibreOffice Calc.

The layout these formulas assume

Cell(s) What goes there
B1 The first day of the month, as a real date (for example 2026-10-01)
B2:AF2 The numbers 1 to 31 (day of the month)
A3, A4, ... One habit per row
B3:AF3, ... A tick for each day: a checkbox, or a typed 1
AH1 Days in the month (formula below)
AK1 Days so far (formula below)
AG / AH / AI Done so far / Month rate / So-far rate for each habit row

If your sheet is laid out differently, keep the logic and change the references.

☐ 1. Get the real number of days in the month

In AH1:

=DAY(EOMONTH($B$1,0))

EOMONTH returns the last calendar day of the month that contains B1, and DAY turns that date into 28, 29, 30 or 31. This fixes February and 30-day months without a dropdown or a long IF chain.

B1 must hold a real date, not text that looks like a date. Google's help page for EOMONTH warns that it needs a cell reference to a date, a function that returns a date, or a date serial number.

Sources: EOMONTH (Google), EOMONTH (Microsoft).

☐ 2. Count only the days that have happened

In AK1:

=MAX(0,MIN(TODAY(),EOMONTH($B$1,0))-$B$1+1)

How it behaves:

  • Current month: today's day of the month (on 18 October it returns 18).
  • Past month: the full length of that month, because MIN picks the last day of the month.
  • Future month: 0, because MAX stops it going negative.

TODAY() is the date of the last recalculation, so the number moves forward each day on its own. Google's TODAY page says it "will always represent the current date the last time the spreadsheet was recalculated".

Source: TODAY (Google).

☐ 3. Count ticks only up to today and only inside the month

For habit row 3, in AG3 (done so far):

=COUNTIFS(B3:AF3,TRUE,$B$2:$AF$2,"<="&$AK$1)

The second condition uses the day numbers in row 2, so:

  • a tick you entered ahead of time on a future day is not counted yet;
  • a stray tick on "day 31" of a 30-day month is never counted.

If you type 1 instead of using checkboxes, replace TRUE with 1:

=COUNTIFS(B3:AF3,1,$B$2:$AF$2,"<="&$AK$1)

Pick one style per row and use the matching criterion. Whether TRUE and 1 match each other in COUNTIFS depends on the app: in LibreOffice Calc they do, because it stores TRUE as the number 1.

Note: Google Sheets and Excel keep logical values and numbers as separate types. We have not verified how COUNTIFS treats a TRUE criterion against typed 1s (or the reverse) in those two apps, so don't mix the two styles in one row.

Note: a ticked Google Sheets checkbox is treated here as the value TRUE, which is how checkboxes commonly behave in formulas; Google's checkbox help page describes custom checked/unchecked values but doesn't spell out the default value. If you set custom values (for example "Yes"), use that value as the criterion instead.

Sources: COUNTIFS (Google), COUNTIFS (Microsoft), Add & use checkboxes (Google).

☐ 4. Show both rates

Month rate, in AH3 (done days in the whole month ÷ days in the month):

=COUNTIFS(B3:AF3,TRUE,$B$2:$AF$2,"<="&$AH$1)/$AH$1

So-far rate, in AI3 (done so far ÷ days so far):

=IF($AK$1=0,"",AG3/$AK$1)

Format both as percentages, then fill the three formulas down for each habit row.

Why both: the month rate answers "how much of this month did I complete?" and starts low by design. The so-far rate answers "how am I doing at the moment?". Early in the month, that second question is usually the one you mean. The IF stops a #DIV/0! error in a future month, where no days have passed.

☐ 5. Check it against a few known cases

Before trusting the sheet, set B1 to a few months and look at the numbers:

Case Expect
Current month, ticked every day so far So-far rate 100%, month rate below 100%
Current month, 10 ticks on day 18 of a 31-day month So far 10/18 ≈ 55.6%, month 10/31 ≈ 32.3%
Last month So-far rate = month rate
Next month So-far rate blank, days so far 0
February in a leap year Days in month = 29
A 30-day month with a tick on day 31 That tick is not counted

☐ 6. Common mistakes that cause a wrong percentage

  • Dividing by COUNTA of the checkbox range. An unticked checkbox still holds a value (FALSE; see the note in step 3), and COUNTA counts every non-empty cell. You get 31 every time, not the days so far.
  • Dividing by a fixed 31 (or by a "days" dropdown). This is wrong in short months, and it gives no so-far view.
  • Mixing checkboxes and typed 1s in one row. Depending on the app, one style may not be counted (see step 3).
  • B1 holds text, not a date. EOMONTH then returns an error. Re-enter the date or use =DATE(2026,10,1).
  • Ticks in columns past the month end. Grey those columns out (conditional formatting on B$2>$AH$1) so nobody types there. The formulas above ignore them anyway.
  • Sharing the file across time zones or opening it late at night. TODAY() follows the spreadsheet's recalculation date, so "days so far" changes at midnight in the spreadsheet's time zone.

Note: the time-zone point follows from how TODAY() works. It is not separately documented on the TODAY help page.
